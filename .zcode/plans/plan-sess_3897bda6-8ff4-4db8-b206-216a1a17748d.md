# Add SecretSpec (https://secretspec.dev/) to lta-rs

Scope: **Config + docs** — no new crate dependencies, no code changes. The library's only secret is the LTA DataMall `AccountKey`, already read from the `LTA_ACCOUNT_KEY` env var by the live test at `tests/bus_stops.rs:132` (skips gracefully when unset). SecretSpec declares that secret and injects it as an env var at test time.

## Changes

### 1. Create `secretspec.toml` (repo root, committed)
```toml
[project]
name = "lta"
revision = "1.0"

[providers]
keyring    = "keyring://"
env        = "env://"

[profiles.default]
LTA_ACCOUNT_KEY = { description = "LTA DataMall API key, sent as the AccountKey HTTP header", required = false, providers = ["keyring", "env"] }
```
- `[providers]` defines the project-level aliases you asked for (`keyring = "keyring://"`, `env = "env://"`).
- `providers = ["keyring", "env"]` on the secret wires those aliases in as the resolution order: OS keychain first, environment fallback. (Drop that field if you'd rather leave resolution to the CLI/user config.)
- `required = false` on purpose: the live test skips itself when the key is absent, so `secretspec run -- cargo test` must not hard-fail for contributors without a key.
- Declares the secret name only — no values, safe to commit.

### 2. Update `.gitignore`
Add `.env` so output from the dotenv provider or `secretspec export --format dotenv` can never be committed.

### 3. Update `README.md`
Currently just a logo. Append a short "Development" section documenting:
- Install the CLI: `brew install secretspec`
- Store the key once: `secretspec set LTA_ACCOUNT_KEY` (saves to the macOS Keychain via the `keyring` provider)
- Run tests with secrets injected: `secretspec run -- cargo test`
- Note: without the key stored, the live download test (`bus_stops_downloads_and_decodes_live_fixture`) skips automatically, exactly as today.

## Validation
- If the `secretspec` CLI is already installed locally, run `secretspec check` to verify the manifest resolves (it will report the key as unset/optional — expected).
- If the CLI is not installed, I won't install it system-wide; I'll note `brew install secretspec` in the summary instead.
- No `cargo test` needed — zero code or dependency changes.
